# FiveM launch curation — 4 September 2026

Initial roster frozen after 83 individual canonical Cfx checks. There are **30 recommended additions**, **25 held candidates**, and **30 exclusion records**. Together with the already-live CaliRP and ProdigyRP, this produces **32 communities**. The target was approximately 40; the shortlist was not padded with unverifiable communities to reach that number.

`fivem-candidates.json` is the review manifest. Only `status: "publish"` entries are recommended for the initial launch. This research did not publish listings, mutate production, contact community operators or join Discord servers. Final publication still uses the existing staff review flow.

## Evidence and selection

- Selection considered published roleplay rules, newcomer guidance, community identity, longevity or recent development, distinct styles, and working entry links. Player totals were not used as a proxy for roleplay quality.
- Primary sources were community-owned websites, handbooks, stores, official Discord profiles and operator-authored Cfx Bazaar threads. Search directories were used only to discover possible codes, which were subsequently checked individually against the official Cfx single-server endpoint.
- Every selected code returned its own FiveM identity and a numeric current player observation during this research. Zero is a valid observation and is not treated as unavailable. All recorded observations are historical snapshots; the live importer must fetch again. Never copy a research count, Discord member total or website total into a live player field.
- Each Discord URL was checked through the public Discord invite API without credentials. A valid invite proves that the invitation resolves; it does not prove server ownership or future validity. Where similarly named communities existed, website and current listing identities were compared before choosing a link.
- Tags and descriptions were rewritten from specific evidence rather than copied from advertising. Rankings, unsubstantiated best-server claims and promotional population claims were removed.
- Framework values retain the normalizer’s evidence where available; an unresolved conflict remains null. Access follows explicit general-entry onboarding where it conflicts with Cfx flags. An application for a police job does not mean the entire server is whitelisted.
- Only one instance per community is recommended. Training, performance-test, development and second public/whitelist instances were omitted. Orange County/OCRP and City of Justice remain excluded at the user’s request.

Raw upstream payloads and player identities are not retained. `fivem-live-checks.json` contains bounded normalized public fields, evidence and timestamps. The checks used 83 explicitly supplied codes with a pause between requests; they did not download the bulk server stream.

## Corrections that must survive review

- **Unknown access:** HighLife, West Coast, Lucid Heights, SAVRP and OzzyGaming DarkSide remain `unknown`. Their departments or advertising did not establish a definitive current general-entry policy.
- **Explicit onboarding over mislabeled flags:** Ignite, District 10 and Logic are allowlisted based on official applications despite public Cfx flags. San Andreas First Response is public with Discord and a guided tutorial required; its official page explicitly says no application despite an allowlisted Cfx flag.
- **Current versus planned access:** Odyssey is currently public. A planned whitelist is not an existing whitelist.
- **Framework uncertainty:** PeakRP remains null because its official custom-framework wording conflicts with current resource detection. Other missing framework values remain null.
- **Identity collisions:** Royalty uses `royalty.gg`, not `royalty-rp.com`. CityLife is not assigned an unverified similarly named domain. SAVRP uses the exact current code from the Strength Online website, not the dead historical code or the unrelated German community. Lucid City, Lucid Heights and LucidRP are not combined.
- **Discord corrections:** Ignite, Liquid, CMG, Circuit, Lucid City and New Day required explicitly checked invite choices. Peak uses `/peakrp`, not the invalid `/peak-rp` website button. Wild Haven uses `/wildhavenroleplay`, not the invalid trailing-d variant.
- **Distinct style:** San Andreas First Response is cooperative first-responder RP against AI incidents, not a conventional civilian/criminal city. Ignite is described as 1980s because its own rules disagree on the exact year.
- **New Day:** retained as a researched hold, not a launch recommendation. Its official community is recognizable, but both current Cfx observations had unavailable occupancy.

## Artwork review

An independent pass fetched the selected artwork through the application’s image boundary and visually inspected a contact sheet. All 31 original candidate logo endpoints returned PNGs; New Day was subsequently held. SAVRP’s generic FiveM top-hat/heart icon was cleared because it was not corroborated community branding.

Six banners were removed from the manifest: Ignite exceeded or failed the safe image boundary; Blaine County and Lucid Heights were unavailable; BlueBird, Popcorn and OzzyGaming were generic Cfx region placeholders. No replacement was invented. The cleared fields and reasons are recorded in `imageReview`.

Vital, Concrete and CMG logos are animated PNGs. Deployment handling must preserve reduced-motion behaviour (for example by storing a static first frame), rather than relying on CSS alone to stop an animated image. This is an implementation follow-through, not a reason to replace the genuine community branding.

## Reproducibility

- `check-fivem.mjs <code> ...`: checks only the explicit codes, saves normalized public data and validates any extracted Discord invite. Run one instance at a time because it updates one JSON file.
- `check-sites.mjs <https-url> ...`: records bounded public-page link metadata for the supplied sources; it does not preserve full pages.
- `check-discord.mjs <invite-url> ...`: records public invite resolution without authentication or joining.
- `build-roster.mjs`: regenerates the manifest from the curated choices and existing check files; it performs no network requests or publication.

Final consistency checks passed: unique canonical codes; English for every recommended addition; numeric observed occupancy for every launch recommendation; validated supplied Discord invitations; HTTPS evidence URLs; description/tag/keyword length bounds; all 83 checked codes classified; cleared image fields retained. Application verification belongs to the main implementation task.
