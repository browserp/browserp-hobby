# Account-removal review display — 8 September 2026

`public/privacy-requests.js` adds an on-demand review section for an active deletion request. It posts only `{requestId: item.id, version: item.version}` to `/api/admin/account-erasure-preflight` through the existing account-bound API wrapper. It neither performs an erasure nor records fulfilment.

The staff workspace must pass `isOwner: state.summary?.permissions?.isOwner === true` to `BrowseRPPrivacyRequests.initStaff`. The display requires that strict owner flag, queue `canFulfill === true`, and a deletion request in `submitted`, `reviewing`, `information_needed` or `ready`. `canFulfill` alone is insufficient: its database helper checks review and fulfilment permissions, which can be delegated. The preflight backend separately enforces the current active owner, permissions, authenticator and request version before releasing a report. The component defaults the owner flag to false.

The display includes owned listings, other owners' adverts using the subject's uploads, stored files, active staff state, the number of record links checked, coverage limitations and all seven fixed review/removal stages. Lower bounds read “At least”; missing storage evidence reads “Not fully checked”. Counts are never summed. Complete bounded checks still require free-text, shared-content, external-copy and backup review.

Only fixed labels, validated numbers, booleans and a formatted timestamp enter the display, using DOM text. No dependency names, paths, triggers, arbitrary evidence, policy prose, metadata, report digest or raw error message are rendered. Request/subject/version bindings and the read-only contract must match; malformed or oversized projections are rejected. Rechecking clears previous results. Existing operation locking, authentication failure clearing, detached-card checks and destruction prevent a late result from restoring private content. Existing review, completion, request history and copy/download controls are preserved.

Local validation on bundled Node 24 passed all 27 tests across `test/privacy-erasure-review-ui.test.mjs` and `test/privacy-requests-ui.test.mjs` (8 new and 19 existing). These checks cover presentation, strict non-owner exclusion, lower bounds, incomplete coverage, malformed and changed reports, safe errors, duplicate scans, permission loss, sign-out, page departure and detached cards. No hosted preflight, database change, deletion or deployment was performed by this UI task.
