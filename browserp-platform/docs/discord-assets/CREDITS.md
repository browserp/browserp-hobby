# BrowseRP Discord emoji pack

Prepared and uploaded 6 September 2026. **40 static emoji are installed: the existing BrowseRP RP mark and 39 Twemoji.** The root task verified **10 of 50 static slots remaining** in Discord emoji settings. This confirms upload and capacity, not bot command or workflow behaviour.

The upload used `/tmp/browserp-discord-emojis/`; that temporary folder is not the durable record. This directory retains the [40-entry source and SHA-256 manifest](manifest.json), this attribution and the [upstream graphics license](LICENSE-TWEMOJI.txt). Emoji images are not duplicated in the repository. Filenames provide meaningful ASCII emoji names.

The 39 functional/reaction images are original Twemoji PNGs (72×72), by Twitter, Inc. and other contributors, sourced from [the maintained upstream repository](https://github.com/jdecked/twemoji) at commit `b6b55fef1e8636b540a6d016a4729ca8cdf2e60b`. Graphics are licensed under [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/); see the [exact upstream license](https://github.com/jdecked/twemoji/blob/b6b55fef1e8636b540a6d016a4729ca8cdf2e60b/LICENSE-GRAPHICS). Original artwork is unchanged; only filenames were changed. These are coherent familiar symbols, not exclusive BrowseRP artwork or an imported third-party meme pack. They use the same recognisable vocabulary as Unicode emoji, with convenient BrowseRP names for operational posts.

`browserp.png` is the existing BrowseRP RP-and-magnifying-glass favicon, copied unchanged at 192×192 from the project. It is separate from Twemoji and is not covered by the Twemoji credit.

## Validation

Every file passed PNG signature, chunk CRC, dimensions and complete-file checks. All are below 256 KB. No raster editing, recompression or generated artwork was used. [manifest.json](manifest.json) records an exact source URL or repository path and SHA-256 for every image; [LICENSE-TWEMOJI.txt](LICENSE-TWEMOJI.txt) preserves the upstream graphics license. These preparation checks are separate from the later Discord upload readback. Neither establishes staff command behaviour.
