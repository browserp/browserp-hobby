# Smart moderation: privacy and operator release notes

Updated 9 September 2026 against combined source `7d9266e031af8a107456d9686c36cb328ca53d56`. This readiness patch supplies conditional disclosure and a synthetic text evaluator; it does not establish hosted state or activate a provider. Main owns integration, migration and release. The existing classifier, moderation authority and picture-review policy are unchanged.

## Release state and public notice

The privacy section describes both provider states conditionally. Publish it only together with the working private-submission, review and free-appeal routes. It explains that enabled checks send submitted comments, proposed names and pictures to OpenAI, including imported OAuth identities; disabled or failed checks leave new submissions privately pending. It makes no claim that external classification is currently enabled or currently disabled. Do not publish the workflow claim against the old immediate-publication upload handler.

The classifier requires both `CONTENT_MODERATION_PROVIDER=openai` and a valid server-side `OPENAI_API_KEY` before a provider request. Reuse the existing configured key; a key alone does not activate the checker. Local patterns cannot approve or block content: they only request review, including when an older rule calls its own match a block. Clean text does **not** automatically publish merely because local rules found no problem. When activated, only sufficiently clear supported text results can approve; uncertainty, invalid coverage, timeouts and failures remain private for staff review. Avatar results can block covered violations but cannot automatically approve the whole image. Applications remain manual. Prior approved identity remains public while a replacement is pending; decisions do not create public warning labels or appeal fees.

The inspected adapter returns policy/checker identifiers, a bounded decision/reason, signal codes, selected category identifiers and threshold/coverage metadata. It discards raw provider responses and local prose reasons. Its database `check_result` field is JSON; keeping it minimal depends on the final caller and server-side validation. Future fields or fallbacks require a fresh disclosure/data review.

## Official OpenAI data handling, checked 9 September 2026

OpenAI's endpoint table lists `/v1/moderations` as not used for training, with no abuse-monitoring retention or application-state retention, and eligible for Zero Data Retention. API training use is off unless explicitly opted in. That table does not establish BrowseRP's account controls, contractual commitments or storage practices. Do not substitute the general 30-day description or advertise account-wide “zero retention.” The same page describes image/file safety-retention exceptions for named other endpoints; verify scope before changing endpoint or adding a fallback. [OpenAI data controls](https://developers.openai.com/api/docs/guides/your-data)

The moderation guide distinguishes text-only categories from supported image categories. Unsupported image categories can have zero scores, so an unflagged avatar is not proof that all relevant risks were checked. [Supported moderation categories](https://developers.openai.com/api/docs/guides/moderation#review-supported-categories)

## Activation and existing privacy responsibilities

Main carries out the requested activation through the existing release gate and configured provider account. Update the public notice **before** live external transmission and verify actual outgoing fields with synthetic content. The text evaluator and its invocation are documented in `SMART_CONTENT_MODERATION.md`; a mock test pass is not evidence of actual model access or threshold quality. Retain the evaluated pinned model and guarded threshold configuration. This patch installs no provider, configures no key, changes no billing and transmits no submitted content.

Keep the website provider flag unset during synthetic evaluation. The evaluator supplies an invocation-local configuration to the actual classifier and never changes the environment or a deployment setting. `CONTENT_WRITES_PAUSED` does not prevent checks during OAuth sign-in, so it is not a substitute for keeping the provider disabled. The existing provider flag covers pictures as well as text; the evaluator tests text only and introduces no separate runtime mode. Pictures still require staff approval before publication.

Candidate/check/appeal records, duplicate-detection fingerprints, quarantine bytes and imported source references remain subject to the existing privacy/erasure workflow. Its retention, permitted-access and backup decisions remain separate from this activation-preparation patch. No duration or automatic deletion promise is introduced here. The table's Auth cascade and asset reference do not settle those decisions or delete bytes, copies or backups.

Keep those decisions separate from technical work: export coverage, retention/cleanup jobs and verification, media retry/recovery handling, and any legacy-public-avatar transition still need implementation or exact integrated evidence. Preserve existing consent/security boundaries and manual data-request fulfilment. All website/Discord role-sync work remains deferred to Dan.
