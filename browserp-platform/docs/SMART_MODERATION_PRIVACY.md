Do not publish the new workflow claim against the old immediate-publication upload handler. Main must verify the final environment still has no activated external checker before releasing the sentence saying submissions are not sent to OpenAI. The current absence of a key/provider activation is the coordinating task's reported configuration, not a secret inspection by this review.

In the inspected classifier, `CONTENT_MODERATION_PROVIDER=openai` and a valid server-side `OPENAI_API_KEY` are both required before any provider request. Without them, a locally established block can remain blocked; other content returns `review`. Clean text does **not** automatically publish merely because local rules found no problem. If later activated, only sufficiently clear supported text results can approve; uncertainty, invalid coverage, timeouts and failures remain private for staff review. Avatar results can block covered violations but cannot automatically approve the whole image. Applications remain manual. Prior approved identity remains public while a replacement is pending; decisions do not create public warning labels or appeal fees.

## Official OpenAI data handling, checked 9 September 2026

OpenAI's endpoint table lists `/v1/moderations` as not used for training, with no abuse-monitoring retention or application-state retention, and eligible for Zero Data Retention. API training use is off unless explicitly opted in. That table does not establish BrowseRP's account controls, contractual commitments or storage practices. Do not substitute the general 30-day description or advertise account-wide “zero retention.” The same page describes image/file safety-retention exceptions for named other endpoints; verify scope before changing endpoint or adding a fallback. [OpenAI data controls](https://developers.openai.com/api/docs/guides/your-data)

The moderation guide distinguishes text-only categories from supported image categories. Unsupported image categories can have zero scores, so an unflagged avatar is not proof that all relevant risks were checked. [Supported moderation categories](https://developers.openai.com/api/docs/guides/moderation#review-supported-categories)
